# StarMap 星图 1.2.0 — 发布说明

> 发布日期：2026-10-27
> 上一个版本：1.1.0（可观测性、三级门禁、刻本口径 UI）
> 主题：**主动发现——把"在监听的"也找出来，且不依赖 nmap。**

---

## 一、为什么做这一版

被动分析回答"网内有什么在通信"。有一类设备天然答不出来：

- 只在自己网段里监听、没有任何会话的服务器；
- 装了服务没接入业务的测试机 / 影子系统；
- 交换机、打印机、摄像头这类只在被访问时才出现的设备。

纯流量视角下它们等于不存在，而这恰恰是政务网监管里最需要说清的部分（账外设备）。
1.2 补的就是这个盲区。

参考了灯塔（ARL）那套资产侦察流水线（快扫 → 服务识别 → 指纹 → 入账），
但做了一个明确的取舍：**不把 masscan / nmap 当作前提**。政务网运维机上装不上外部工具是常态，
"装不上就等于没有主动发现能力"不是可接受的答案。

| 灯塔的做法 | StarMap 1.2 的形态 | 原因 |
|---|---|---|
| masscan 全端口快扫 | 纯 Go TCP connect 扫描，三档端口集 | 无外部依赖、无需 root、到处能跑；代价是慢，用限速换稳定 |
| nmap `-sV` 服务识别 | 自持 70 条指纹规则 + TLS/banner/favicon | 规则优先国产内网设备；不做模糊猜测 |
| Redis 队列 + 多 Worker | 进程内 goroutine + 令牌桶 + 时间窗口 | 单机单二进制部署，不引入中间件 |
| Web 爬虫 / 目录爆破 | **不做** | 目录爆破是渗透测试动作，超出资产测绘的授权范围 |

## 二、这一版交付了什么

1. **内置端口扫描**（`internal/probe`）：三档端口集、令牌桶限速、ctx 可中断，无需 root / 外部命令。
2. **服务指纹**：HTTP（状态码 / Server / 标题 / 跳转）、TLS（CN / SAN / 签发者 / 到期 / 自签）、
   banner（SSH / FTP / SMTP / MySQL / Redis 等首包）、favicon mmh3，共 70 条规则。
3. **编排器**（`internal/discover`）：先端口后指纹；时间窗口、失败退避、已知主机降频；
   手动触发与周期任务共用一份执行逻辑。
4. **接口与配置**：`/api/discover/run|status|plan`，10 个 `discover_*` 配置项全部可热改。
5. **界面**：端口记录 tab 的「深度发现」弹窗、端口表新增「指纹」列、系统配置新增「资产与扫描」分组。

细节、动机与踩坑记录见 [CHANGELOG](../CHANGELOG.md) 的 1.2.0 条目。

## 三、升级注意（从 1.1.0 升上来）

| 项 | 说明 |
|---|---|
| 数据库 | `ports` 表在线 `ADD COLUMN` 加 7 列，**不重建表**。老库直接启动即可，无需迁移脚本。 |
| 兼容性 | 端口表原有数据指纹列为空，界面显示 `-`；不影响既有功能。 |
| 默认行为 | `discover_enabled = false`。**升级后不会自动开始扫描**，需管理员在「系统配置 → 资产与扫描」显式开启。 |
| 授权 | 端口扫描会在目标侧留下大量连接记录，与 ARP/ICMP 探活是两种授权风险。政务网常常只批前者，所以独立开关、默认关闭。 |
| 周期任务 | `discover_sec = 0` 表示"仅手动触发"；要定时扫必须同时配置 `discover_sec > 0` 与 `discover_cidrs`。 |

## 四、验证方式（可复跑）

```bash
# 1. 全量测试
go test ./...

# 2. 覆盖率 + 门禁（新增 probe / discover 两条核心包下界）
go test ./... -coverprofile=coverage.out
scripts/coverage-gate.sh coverage.out 72

# 3. 端到端（灌合成 PCAP，断言事件 / 拓扑 / 复核 / 去重）
scripts/e2e.sh

# 4. 前端交互冒烟（真浏览器；需先起一个灌好数据的实例）
AUTH_BASE= python scripts/ui-smoke.py

# 5. 截图（只重拍变化的）
STARBASE=http://127.0.0.1:18097 STARDISCOVER=127.0.0.1 \
  SHOTONLY=settings.png,ports.png,discover.png python scripts/shot.py
```

本轮实测：`go build` / `go vet` / `go test ./...` 全绿；全仓覆盖率 **73.3%**；
`internal/probe` 83.7%、`internal/discover` 81.7%；前端冒烟（含深度发现与拓扑下钻）通过。

## 五、已知边界

- **慢**：TCP connect 扫描比 SYN 扫描慢一个量级，`full` 档扫 /24 是小时级。这是刻意的取舍——
  ICMP 在内网大面积屏蔽、ARP 只限同广播域、nmap 常常装不上，connect 是唯一"到处都能跑"的手段。
- **指纹长尾**：70 条规则覆盖不了长尾产品；未命中时只留标题 / banner 原文，不做模糊猜测。
  宁可不给结论，也不给错误结论。
- **无爬虫**：不产出 URL / 目录清单，原因见上（授权边界）。
- **单机**：无分布式调度，多网段大规模扫描靠调低速率 + 拉长窗口，不靠加机器。
- **前端自动化**：仍只有发布前的 `ui-smoke.py` 手动闸门，未进 CI（浏览器下载在内网/CI 不可靠）。
