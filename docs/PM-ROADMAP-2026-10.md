# StarMap 产品路线图（2026-10）

> 角色视角：产品负责人（PM）。本文回答三个问题：**为谁做、做什么、先做什么**。
> 目标：把 StarMap 从「能跑的资产测绘工具」推进到「**真实可用的企业级内网测绘与违规监测平台**」。

---

## 1. 产品定位（一句话）

> **面向政务网 / 隔离内网，用被动流量绘制可自生长的全网拓扑，并持续发现违规接入（多网融合、隧道、账外设备）。**

**不做的事**（划清边界，避免摊大饼）：
- 不做漏洞扫描器（不是漏扫/NAS 的替代品）
- 不做流量全包留存（不做 NDR 的 PCAP 回溯仓）
- 不做攻击侧工具（只做防御侧资产与违规监测）
- 不做通用 CMDB（只做「流量实证」的资产视图）

**核心差异点**：**流量实证 + 只打标签不定性 + 单二进制内网离线部署**。这三点是竞品（ARL/灯塔偏主动扫描、商业 CAASM 需私有化交付）做不到的组合。

## 2. 目标用户与场景

| 用户角色 | 典型诉求 | 成功判据 |
|---|---|---|
| **政务网安全运营工程师**（主用户） | 网内到底有什么设备？哪些是台账外的？有没有一机两网/私搭隧道？ | 打开平台 30 秒内能回答「哪个网段有几台、哪几台可疑」 |
| **等保/密评整改负责人** | 资产底数、违规外联证据、整改前后对比 | 能导出可交差的资产清单与违规清单 |
| **上级监管/巡检组** | 抽查某网段是否纯净、是否有多网融合 | 能按网段下钻，逐台核对 |

**关键场景约束**（决定产品形态）：
1. 环境隔离、**不能连外网** → 零 CDN、零云端依赖（已满足）
2. **不能随意主动扫描**（监管敏感）→ 主动发现默认关闭、需显式授权（已满足）
3. 单人/小组运维 → **一键部署、单二进制**（已满足，不能破坏）
4. 网段多、设备杂 → **自动化程度决定可用性**

| 优先级 | 事项 | 价值 | 成本 | 依据 |

| **P0（本次）** | 新网段自动识别 | 高（自生长闭环最后一块） | 低（1-2 天） | 直接服务主线「全网自生长」 |

## 5. 里程碑

### V1.4（已完成）
多网融合按 /24 判定 · 聚合丢资产 P0 修复 · 自动发现周期扫描 · 网段清单视图 · 探针模拟器

### V1.5（已完成）
- **新网段自动识别**（P0）：流量里出现新 /24 → 自动纳入扫描范围，防误扫
- 验收：模拟新网段流量后，自动发现任务在下一轮自动覆盖该网段，日志可见

### V1.6（已完成）
主题：**让异常在大网里藏不住，让下钻视图真正可读**（不是新增功能面，而是把主线的"可见性"补齐）
- **风险锚点**：中/高风险节点不参与网段聚合，始终单独呈现（红虚环）。理由：聚合阈值一旦触发，异常设备会被折叠吞掉，恰好藏起最该看见的那台；正常网络无中/高风险节点，对常规大网零成本。
- **归属边 `Kind=owner`**：按 IP 的 /24 归属推导虚线关联，双归属主机同时连到两个网段聚合节点 → 一机两网在拓扑上直接可见（不依赖"该网段内恰好有内部对端"）。
- **修下钻丢边（P1）**：成员被映射成自身聚合身份导致网段内链路全丢，下钻只见孤立圆点；改为真实成员身份 + 上下文节点补全。
- **修泳道层名错位**：层号压缩后仍按压缩索引取层名（「外部网络」里放主机）。
- 验收：模拟器灌入政务网 4 场景后，总览见 3 个红虚环锚点、2 个网段聚合（9/5 台）；下钻 10.10.1.0/24 得 12 节点 / 11 边且无端点缺失，双归属锚点同时连 10.10.1.0/24 与 172.16.5.0/24。

### V2.0（下一阶段，按 P1 顺序）
1. 拓扑聚合/展开可视控制（大网密度与视线管理，V1.6 已解决"异常不被折叠"，仍缺"正常成员按需展开"）
2. 台账导入对照（CSV → 账外/僵尸资产）
3. ~~报告导出~~（由专业系统承担，不做）

## 6. 本次迭代范围（V1.5：新网段自动识别）

**问题**：当前自动发现只扫配置的固定 `auto_discovery_cidrs`。网内新出现网段（新 VLAN、临时拉线、新增业务区）不会被自动覆盖，拓扑"长不全"。

**方案**：
1. 新增开关 `auto_discovery_follow_discovered`（默认 **false**）
2. 开启后，每轮扫描目标 = 配置的 cidrs ∪ **流量已发现的全部内网 /24 网段**
3. **防误扫三重约束**：
   - 只取内网网段（`IsPrivate` 校验，天然排除公网）
   - 支持 `auto_discovery_exclude_cidrs` 排除列表（链路本地 `169.254.0.0/16`、容器网段等）
   - `auto_discovery_max_cidrs` 上限（默认 64），防止网段爆炸拖垮扫描
4. 新网段首次出现时打日志（`[auto-discovery] 发现新网段 xxx`），便于审计

**验收标准**：
- [ ] 开关关闭时行为不变（只扫配置 cidrs）
- [ ] 开关开启后，流量出现新 /24 → 下一轮自动被扫描
- [ ] 排除列表生效（配置的网段不被扫）
- [ ] 上限生效（网段数超上限时截断并告警）
- [ ] 单测覆盖：内网校验、排除、上限

## 7. 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| 自动跟随导致**扫描面失控** | 高（监管敏感） | 默认关闭 + 排除列表 + 上限 + 日志可审计 |
| 大规模下扫描本身消耗资源 | 中 | 间隔可配 + 上限 + 只扫 /24 |
| 单人维护能力边界 | 中 | 坚持「不做清单」，拒绝过度设计 |
| 主动扫描的合规边界 | 高 | 默认关闭 + 文档明确「需获授权」 |

---

## 8. 一句话结论

**主线是「自生长的全网拓扑 + 违规接入监测」，一切功能先问「是否服务于看清全网 / 发现违规」，不服务的坚决不做。**
