# StarMap 1.7.2 发布说明

> 主题：**三个"接口 200、单测全绿、界面上不报错"的问题——只有以用户的方式走一步才会露出来。**
> 发布日期：2026-11-01 · 上一个正式版：1.7.1 · 无 schema 变更，可直接替换二进制

---

## 一、这一版在解决什么

1.7.1 修的是"长期在线跑才暴露"的账。这一版换了个方向：**把每个写入口真点一遍**，
再每一页量一遍布局。三个缺陷全部来自这一步，读代码和跑单测都发现不了：

| 现象 | 看起来像 | 实际是 |
| --- | --- | --- |
| 配置改完存不了 | "按钮在顶上，滚回去点一下就行" | 页头不吸顶，按钮在视口外 **4400px** |
| 任务详情写着"结束时间 0001-01-01" | "界面小 bug" | 零值时间被序列化，且前端把非空字符串当真 |
| 报表控制台一条 404 | "无所谓" | 自包含 HTML 没声明 icon，离线交付时会带瑕疵 |

所以这一版除了修，还补了一道**可重复执行的闸门**：`scripts/visual-audit.py`。
"看起来是对的"从此要变成"量出来是对的"。

## 二、配置页的保存按钮会随内容滚走

### 问题

配置页有 30+ 项，按「探测与采集 / 拓扑引擎 / 检测规则 / 资产与扫描 / 威胁情报」分组。
页头（标题 + 两个按钮）不吸顶，`position: static`。实测滚到底部时：

```
「保存配置」按钮  top = -4458     inView = False
```

也就是说：用户在最后一组改完 `discover_rate_pps`，必须**手动滚回页面顶部**才能保存。
下拉、开关改了一堆，滚回去的路上还看不到自己改了什么。这不是"不够顺手"，是"改完存不了"。

### 修法：吸底操作条

- 新增 `.sm-actionbar`：**页头工具栏离开视口后才出现**，页面回到顶部时隐藏——
  同一屏永远只有一套保存按钮，不会出现"两个保存不知道该点哪个"。
- 用 `IntersectionObserver` 观察页头工具栏，而不是判断 `scrollY > N`。
  页头高度随视口宽度折行变化（窄屏 h1 与按钮会换行），写死阈值在某些宽度下必然错判。
- 用 `position: sticky; bottom: 0` 而不是 `fixed`：sticky 元素仍在文档流里占位，
  滚到页面底部时不会盖住最后一组配置项；`fixed` 会。
- 隐藏态是 `opacity:0 + translateY(100%) + pointer-events:none`，
  不是 `display:none`——后者会让过渡动画失效，出现"啪"一下跳出来的观感。

### 判据

自动化断言四件事，缺一条都不算修好：

1. 顶部：页头按钮在视口内，**且**吸底条隐藏（`opacity ≈ 0`）；
2. 滚到底部：页头按钮已离开视口（缺陷的复现条件成立）**且**吸底条按钮在视口内；
3. 改值 → 用吸底条保存 → toast 出现；
4. reload 后回读一致（证明真的落库，不是前端假成功），再还原。

## 三、任务账的时间字段：两种口径 + 一个 0001 年

### 问题一：同一个字段两种格式

`/api/tasks` 的 `started` 有两条来源：

- 刚跑完的任务走内存态（`time.Now()`），序列化带本机时区 → `2026-11-01T15:29:16+08:00`
- 进程重启后从 `discover_tasks` 读出来是 UTC → `2026-11-01T07:29:16Z`

同一个字段、同一个值，两种字符串。前端 `new Date()` 两种都能解析，所以界面上看不出来；
但导出 CSV、写脚本、以后接别的消费方，按字符串比对就会错。全站其它接口都是 RFC3339 UTC，
任务账没有理由例外。

### 问题二：运行中的任务"结束时间 0001-01-01"

未结束任务的 `Finished` 是 `time.Time` 零值，而 `encoding/json` 的 `omitempty`
**对结构体无效**（永远非空）。于是运行中的任务回：

```json
"finished": "0001-01-01T00:00:00Z"
```

前端判断写的是 `t.finished ? UI.fmtTime(t.finished) : '—'`——非空字符串恒为真，
详情抽屉里就把结束时间印成 `0001-01-01 07:56:02`（东八区换算还多了个时分秒）。

### 修法

- 给 `discoverTask` 加 `MarshalJSON`，在**出口处**统一：时间转 UTC RFC3339，零值输出空串
  （配合 `omitempty`，键直接不出现）。一处收口，覆盖列表 / 详情 / 状态接口 /
  内存态 / 库内态五条返回路径。
- 前端 `fmtTime` / `fmtTimeShort` 加零值兜底（`getFullYear() <= 1` 回 `-`）：
  渲染层不该把"没有"画成"有"。任何一处漏了归一化，也不至于再印出年份 1。

### 判据

`TestTaskTimesSerializedUTC` 刻意用 `FixedZone(+8)` 构造内存态任务：

- 断言 `started` 以 `Z` 结尾且能按 RFC3339 解析；
- 断言 `finished` 键不存在或为空串；
- 用 `FixedZone(+8)` 而不是"本机时区"的原因：CI 跑在 UTC 上，旧实现同样回 `Z`，
  "带时区"这个缺陷会被环境掩盖掉。

反向验证过：把 `MarshalJSON` 换回裸序列化，用例立刻失败并打印
`任务 live-1 的 started 不是 UTC（"2026-03-04T13:06:07+08:00"）`。

## 四、报表的 `/favicon.ico` 404

`GET /api/report` 输出的是一份**自包含 HTML**（要能单独存下来、能发邮件、能直接打印），
但它没有声明 icon，浏览器会去请求默认的 `/favicon.ico`，在没有该路由的实例上留一条控制台报错。

修法不是加一条 `/favicon.ico` 路由，而是在模板里**内联** favicon：

```html
<link rel="icon" href="data:image/svg+xml,%3Csvg ...%3E">
```

换成站内相对路径（`/assets/favicon.svg`）会把控制台的 404 消掉，但代价是
**报表被单独保存/发出后图标变死链**——这条"单文件可离线交付"的产品承诺比一条 404 重要。

## 五、`scripts/visual-audit.py`：视觉开始有断言了

逐页实测、给出非零退出码：

| 判据 | 为什么要量 |
| --- | --- |
| `scrollWidth - innerWidth > 0` | 横向滚动条是最容易被截图缩放假阳/假阴的 |
| 单行文本 `scrollWidth > clientWidth` 且未用省略号 | 文字被裁，肉眼在缩放图上看不出来 |
| `getBoundingClientRect` 出视口 | 元素跑出可视区，静态截图完全看不到 |
| 按钮/下拉/输入框高度 < 24px | 手不好点 |
| `pageerror` / console error / 4xx | 功能坏了但页面还"看着正常" |
| 配置页滚到底部的保存按钮位置 | 就是第二节那个缺陷的回归闸门 |

跑两遍视口（1440×900 与 2560×1440），因为宽屏拉伸会暴露另一类问题。
报表页也在闸门里——它是唯一会被单独带走、在别人机器上打开的页面。

写这个脚本时它先暴露了**判据本身**的三处假阳性，一并记下来免得后人重踩：

- 抽屉常驻 DOM 停在 `right:1920`，只排除 `position:fixed` 不够，**子元素**照样报"出界"；
- SVG `<text>` 没有 `clientWidth`（恒 0），按 HTML 的裁切判据会整片假阳性 → 只查 HTML 命名空间；
- 页脚行内链接 17px 高是排版不是缺陷 → 触达尺寸只量按钮/下拉/输入框。

## 六、截图补全

`docs/screenshots/` 此前只有 1.0~1.3 的页面：`sites / changes / tasks` 以及站点抽屉、
任务抽屉、测绘报告一张都没有。**"截图能证明功能好"这句话在当时是不成立的。**

这一版补齐到 20 张，并新增 `docs/screenshots/README.md`（`shot.py` 的文档字符串一直在引用它，
但文件并不存在）：起实例 → 灌数据（探针 / PCAP / 端口 / 扫描 / 台账五步）→ 拍摄 → 校验。

新增的复现说明里特意写死了两条规矩：

- **增量更新用 `SHOTONLY`**：拿数据很少的实例跑全量，会把已拍得比较饱满的图覆盖成空表，
  而 git 里只看到"图片变了"，很难察觉变差了；
- 台账必须能同时体现四类差异（在册在网 / 台账外 / 台账僵尸 / IP 不符），否则那一页讲不清"账实对照"。

## 七、升级

无 schema 变更，直接替换二进制即可。

```bash
# 从 1.7.1 升级
systemctl stop starmap
install -m 0755 starmap-linux-amd64 /opt/starmap/bin/starmap
systemctl start starmap

curl -s localhost:18080/health   # version 应为 1.7.2
```

配置页的吸底操作条只影响前端，无需改配置；任务账时间口径变化只影响**新产生**的响应
（库里的历史行不改写，接口出口统一归一化）。

## 八、已知限制（未在本版处理）

- 站点列表超过 2000 条时前端只能拿到前 2000 条（服务端分页仍在 1.8 待办）；
- 告警通道（邮件 / Webhook / 企业微信）未接入，本版仍只做界面展示；
- 实时抓包依赖编译期 libpcap/npcap，官方二进制未编译该能力：按钮会置灰并在页面上写明原因，
  离线 PCAP 导入与探针上报不受影响。

> （`v1.7.2-0.20261101080007-8bef6e2e79d2`）写进二进制，同一份源码 SHA256 就变了。
> 正确顺序是 `commit → tag → build`；本次已按此顺序重出全部八个产物，
> 并核对过 GitHub Release 上的 `digest` 与本地一致。
